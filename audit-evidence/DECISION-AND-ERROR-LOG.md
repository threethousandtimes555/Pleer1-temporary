## Важное предупреждение о репозитории

Этот журнал находится в **Pleer1-temporary — временном публичном репозитории**. Он предназначен для временного аудита и экспериментов, а не для хранения постоянной истории проекта.

- Не добавлять сюда пароли, токены, ключи API, персональные данные, приватные переписки, секреты или иные чувствительные сведения.
- Не переносить изменения из временного репозитория в основной Pleer1 без отдельного согласования.
- Перед удалением временного репозитория согласовать, какие безопасные записи и результаты нужно сохранить в основном проекте.
- Публичные записи должны содержать только информацию, которую допустимо раскрывать всем.

## Правила ведения журнала

1. Фиксируем гипотезы отдельно от подтверждённых фактов.
2. Проверяем выводы ChatGPT и Qwen независимо; совпадение двух моделей само по себе не считается доказательством.
3. Для каждого существенного вывода указываем проверку: исходный код, diff/commit, лог, артефакт CI, скриншот или воспроизводимый тест.
4. Не переписываем первоначальные предположения задним числом. Исправления добавляем новой записью или обновлением статуса с сохранением истории через Git-коммиты.
5. Если данных недостаточно, прямо пишем «не подтверждено» или «нужны дополнительные данные».
6. Отмечаем как ошибки моделей, так и ошибки процесса, тестов и инженерных решений.
7. Записываем успешные решения и регрессии, чтобы не повторять уже пройденные эксперименты.

## Статусы

- **Гипотеза** — возможное объяснение, ещё не проверено.
- **На проверке** — тест или независимый разбор выполняется.
- **Подтверждено** — есть воспроизводимые доказательства.
- **Опровергнуто** — проверка показала, что гипотеза неверна.
- **Частично подтверждено** — верна только часть предположения.
- **Нужны дополнительные данные** — имеющихся доказательств недостаточно.
- **Исправлено и перепроверено** — изменение внесено и повторная проверка прошла.

### Запись №018 — выяснение, почему прежний «найденный трек» запускался

- **Дата:** 18.11.2026
- **Область:** SearchModel / Jamendo / Player playback / корректность старого UI-теста.
- **Уточнение пользователя:** результат «Джем – я молодой вампир vamp» относится к Jamendo, а не подтверждает поиск отдельного YouTube-видео. Отдельно выяснить, почему этот результат вообще запускался.
- **Подтверждённый путь в коде:**
  1. Старый и текущий `SearchModel.run` запускает источники параллельно; если Jamendo включён и задан `client_id`, вызывается `Sources.jamendo`.

Старый тест проверял текст совпадения в общей выдаче и не фиксировал source tag, ID или YouTube video ID. Факт запуска — совместим с Jamendo-потоком и не является подтверждением YouTube.
- **Изменение регрессионного теста:** в рабочей ветке commit [e66d0557](https://github.com/threethousandtimes555/Pleer1/commit/e66d0557fad1c2c08b3e7fd081b6814132a8a001) заменил неоднозначный запрос `я молодой вампир vamp` на контрольный запрос `Crystal Castles Concrete`. Проверка по-прежнему требует accessibility identifier `search.result.youtube.track`, который назначается только трекам с YouTube ID-префиксом `y`, без playlist/radio ID.
- **CI:** run #29 [44204680947](https://github.com/threethousandtimes555/Pleer1/actions/runs/44204680947) на предыдущей версии теста ещё выполнялся; run #30 [44205081047](https://github.com/threethousandtimes555/Pleer1/actions/runs/44205081047) на обновлённом запросе находится в состоянии pending. По ранее предоставленному экрану Codemagic build overview: ветка `fix/youtube-standalone-search-device-2026-11-19`, commit `ec7bfe8f0fef22eb5fe0c2eb28573309de484db4`; сборка началась 19.11.2026 в 00:08 UTC. Этот commit добавляет Codemagic workflow; его родительская история содержит исходный код, вошедший в сборку. Более поздний commit `a64ced41faf9fc93ec187c2d071e904bf0d1692b` (00:59 UTC) уже не входит в эту IPA. Он меняет только классификацию поиска коллекций через `YouTubeSearchIntent` (всегда возвращает true).
- **Контрольная точка:** Build #14 — `Pleer1` commit `14956c5fbe07d39af97f73d4b462efc3fb42e66f`. Источник текущей Lab-разработки восходит к оригинальной рабочей ветке `Pleer1/work/restore-youtube-module-2026-11-17`, commit `dc7b177617625e96eb233802ae647d3e5b3ac680`, которая на 48 коммитов опережает Build #14. Сверка Git trees: Build #14 — 28 entries, кандидат IPA — 32; в обеих версиях присутствуют основные файлы под `plei/Sources`, но набор корневых/служебных файлов отличается. Не называть весь tree побайтно идентичным.
- **Resolver — ключевой результат:** `YouTubeEngine.resolve(videoID:)` в Build #14 и кандидате IPA идентичен целиком (5623 символа в извлечённом блоке). `makeClientContext` также идентичен. HTTP `post` формирует те же заголовки, client name/version и тело запроса. Три клиента совпадают: VISIONOS 1.02 / 101, ANDROID_VR 1.60.19 / 28, IOS 20.10.4 / 5. Жизненный цикл visitorData и его TTL в сравнённых файлах также не менялись. Отличия `YouTubeEngine.swift` относятся к поиску, фильтру видео, классификации коллекций и диагностике парсера, а не к Resolve. Поэтому прежняя гипотеза «мы изменили client context/Resolver и этим сломали ролик» текущим diff не подтверждается.
- **Ограничение по UNPLAYABLE:** текущий лог фиксирует HTTP 200 + UNPLAYABLE у всех трёх клиентов, но не содержит полного `playabilityStatus`/error-screen payload и фактического значения visitorData. Поскольку код Resolver одинаков, остаются динамические различия ответа YouTube и данных запроса (включая конкретный visitorData, сетевой/серверный контекст и состояние видео). Ни одна из этих причин пока не доказана. Пользователь подтверждает, что ролик ранее играл на Build #14 и был доступен; нельзя объявлять его удалённым/приватным.
- **Player.swift:** между Build #14 и кандидатом IPA идентичны `load()`, `loadYouTube()`, `finishCurrentItem()`, `tick()`/watchdog, `planNext()`, `reconcileYouTubePrefetch()`, `prefetchNext()` и `advance()`. Реальные отличия: повторная активация AVAudioSession в YouTube start/readyToPlay; дополнительный resume при readyToPlay, если пользователь не поставил паузу и нет interruption; диагностическое логирование seek с completion callback. Сам вызов `player.seek(to:)` сохранён; seek не удаляет end observer и не меняет loadToken. Следовательно, связь seek с пропуском автоперехода не доказана.
- **Duration — важная связка:** `loadYouTube()` и `tick()` идентичны Build #14. В `tick()` UI position ограничивается `knownYouTubeDuration`, а UI duration также выставляется из него; watchdog сравнивает с known duration сырой AVPlayer clock и считает near-end всё время после expected-3 сек, но вызывает finish только при остановке clock на 5 секунд. При расхождении 188/376.72 или 210/419.03 UI может показать 100% примерно на половине реальной длительности AVPlayer item. Это подтверждённый риск неверного отображения/раннего near-end окна, но не доказанная причина пропуска finish event.
- **Автопереход:** тест с ручным seek остаётся единственным сообщённым случаем отсутствия перехода; предоставленный фрагмент не содержит достаточной последовательности finish_event/advance, чтобы установить точную причину. Отдельный фоновый тест не проверял естественное окончание первого трека: пользователь нажал Next вручную. На следующем треке watchdog действительно выполнил auto-advance. Значит, автоматический путь работает хотя бы в одном сценарии; универсальная исправность не доказана.
- **Prefetch и длинный старт:** `prefetchNext()` в сравнённых версиях идентичен и заранее выполняет Resolve следующего YouTube ID; он не создаёт AVPlayerItem и не доказывает предварительную загрузку аудиоданных/gapless. Успешный prefetch в playlist test подтверждает только разрешение потока. Долгое ожидание 24-минутного сборника произошло после успешного Resolve при AVPlayer waiting / loaded range=0; это отдельная проблема старта/буферизации, не поиска.
- **Хэширование:** `Media.swift` полностью идентичен Build #14 и кандидату IPA. В нём уже есть DJB2-хэш от Track ID для имён файлов локального AudioCache. Он не кэширует YouTube stream URL и не ускоряет получение/буферизацию сетевого аудио. Криптографический hash сам по себе не ускорит playback.
- **Обложки:** `Media.swift` идентичен. `ArtView` использует `.resizable().scaledToFill()` и `.clipped()`; изменения `Views.swift` не затрагивают этот layout. Исправление обложек не внесено. Чёрные полосы могут быть частью исходного thumbnail; нужны размеры исходного изображения и фактические ограничения контейнера, прежде чем менять scaling.
- **Поиск:** в кандидате IPA есть новые изменения поискового пути: обычный запрос может включать video filter, коллекции включаются по распознанным словам playlist/Mix; исправлена дедупликация, чтобы уже добавленные видео не отфильтровывались повторно. Тест `crystal castles mix` дал 16 видео и 3 playlist, radios=0; playlist browse дал 31 трек. Commit `a64ced4` после сборки изменил intent так, чтобы коллекции включались всегда; эта версия не входит в установленную IPA и не должна приписываться её тестам.
- **Пересмотр прежних предложений:** (1) изменение Resolver request context как установленная причина — не подтверждено diff; (2) seek как причина пропуска observer — не подтверждено кодом; (3) оптимизация ожидания HTML fallback относится к задержке выдачи результатов поиска, а не к долгому старту уже выбранного аудио; (4) hash не решает сетевую буферизацию; (5) prefetch URL не равен gapless. Эти направления не использовать как основания для немедленного патча.
